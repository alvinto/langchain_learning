What & Why

LangChain 是什么

开源的 Agent / LLM 应用开发框架（langchain 等 pip 包）：统一模型与组件抽象，LCEL 可组合流水线。

LangSmith 等为可选商业平台 · 复杂状态编排见 LangGraph

痛点 1 — 各厂商 API 差异大，换模型成本高
痛点 2 — RAG / Tool / Memory 每次从零拼装
痛点 3 — Agent 循环、分支、恢复无统一范式
痛点 4 — 缺观测与调试，生产难运维

→ 提供组件 + 编排 + 可观测性

Core · 01

State + Node + Edge

LangGraph 把 Agent 流程建模为状态机：共享 State 在节点间流转，边决定下一步。

  • State — TypedDict / MessagesState，定义图内共享字段
  • Node — 纯函数 (state) → 部分更新，只返回变更字段
  • Edge — 普通边固定跳转；条件边按 state 动态路由
StateGraph(State)
  .add_node("count", count_words)
  .add_edge(START, "count")
  .add_edge("count", "upper")
  .compile()

Core · 02

model ↔ tools 条件循环

create_react_agent 底层就是两个节点 + 一条条件边 + 回环边。

  • model 节点 — bind_tools 后 LLM 决定是否出 tool_calls
  • tools 节点 — ToolNode 执行工具，写回 ToolMessage
  • tools_condition — 有 tool_calls → tools，否则 → END
.add_conditional_edges(
    "model", tools_condition,
    {"tools": "tools", END: END})
.add_edge("tools", "model")

Core · 03

Checkpoint 持久化

每次 invoke 后自动保存 State；同一 thread_id 下次调用可恢复上下文。

  • MemorySaver — 内存 checkpointer，开发调试够用
  • thread_id — 按会话隔离 checkpoint，多用户互不干扰
  • MessagesState — messages 字段自动累加，适合 Chatbot
.compile(checkpointer=MemorySaver())
cfg = {"configurable": {"thread_id": "t-1"}}
graph.invoke({...}, config=cfg)  # 多轮同 thread

Core · 04

Human-in-the-loop

敏感操作（删库、转账）在进节点前暂停，等人审批后再续跑。

  • interrupt_before — compile 时声明暂停点，如 ["tools"]
  • 第一次 invoke — 图跑到 tools 前停下，返回待审批 state
  • 第二次 invoke(None) — 沿用 checkpoint 从暂停处继续
.compile(
    checkpointer=MemorySaver(),
    interrupt_before=["tools"],
)
state = graph.invoke({...}, config=cfg)
state = graph.invoke(None, config=cfg)

需要可恢复会话、人工审批或Multi-Agent 并行时上 LangGraph；其余优先 create_agent。
